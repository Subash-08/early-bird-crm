# Booking, Operations and demo data

## What changed

- **Bookings** is the handoff from an accepted quotation. It holds the booking number, selected option and agreed price, trip dates, travellers, contact and billing details, optional invoice, and the coordination checklist. A booking created from a newly approved quotation starts as **Ready for coordination**. The Owner starts coordination without recording a payment or issuing an invoice first.
- **Booking changes** is the sidebar name for `/settlements`. Use it for changes and cancellations. New bookings have no Payments tab, transaction entry, expense recording, or settlement closure. Historical payment-tracked bookings retain their balances, transactions and existing release rules. Older approved quotes without the new approval marker retain their historical behavior if converted later. Quote prices and optional invoice amounts are still available.
- **Operations** holds reusable supplier contacts and vehicle records, plus booking-specific services, trips, readiness checks, documents, and incidents. Suppliers and vehicles are reusable records. Incidents belong to the affected booking or trip. The Owner or assigned Sales coordinator can reuse the same supplier when confirming more than one service.
- **Copy package services** copies stays and transport from the accepted quote into Operations as drafts. It uses rows for the chosen option plus shared rows, skips transport marked Not required, and preserves who is arranging each leg. Hotel dates are carried as notes so staff can verify check-in times. A transport date/time is set automatically when it is usable in India time. The coordinator chooses the supplier and verifies the final details. Repeating the copy skips rows previously copied and preserves edits. Separately created manual rows remain separate. The accepted quote and its PDFs are immutable.
- **Demo templates** contain Andaman, Kerala, Kashmir, Gangtok and Darjeeling, and Shimla and Manali. The templates include day plans, hotels, transport, meals, sample option prices, and selected extras from the supplied documents. Check prices, closures, permits and terms before sharing. Kashmir needs a manual check of the base city and glacier/pony inclusions. Reusable templates omit historical dates, payment instructions and private contact details.

## Development setup

Run `npm run db:seed-demo` from the CRM directory with `APP_ENV=development` configured for your test database. It adds missing demo rows by stable ID and does not overwrite existing records. It does not insert fake bookings, supplier confirmations or financial transactions. Use a demo enquiry to exercise acceptance and conversion.

## Manual checks

1. **Owner and Sales** — Find the seeded Andaman, Kerala and Kashmir templates. Start a quote with a matching destination, apply a template, set dates and travellers, and check the pricing and inclusions. For Sikkim, use the destination **Gangtok and Darjeeling**. Check both Andaman ferry directions and both Kashmir hotel options. Re-run the seed in a development database and confirm each template appears once.
2. **Booking** — Approve, share and accept a new test quote. Create the booking twice. Expect one booking in **Ready for coordination**. Check the accepted price and option, travellers and invoice tab, then confirm there is no payment tab. Start the checklist without an invoice or advance as Owner. Try releasing as Sales and expect it to be blocked. Issue an invoice separately if needed and check that it contains priced lines without the payment summary.
3. **Service copy** — From **Operations → Bookings → Services**, copy package services on a released booking. For Kashmir, expect only the chosen hotel's row plus the shared transport. For Andaman, expect two ferry legs. Check that all copied services are Draft and have no supplier assigned. Change a draft, then copy again and confirm the edit survives. Try with no applicable stays/transport and expect a clear message. Try with a cancelled or completed booking and expect the action to be blocked.
4. **Supplier, vehicle and incidents** — Create a test supplier in Operations and select it on a copied service. Sales can save a draft and Owner confirms the agency commitment. Create a vehicle and assign it only for an internal-driver trip. Report a trip incident and check that trip completion requires its resolution. With separate driver sessions, confirm an unrelated driver cannot see or change the booking.
5. **Changes and historical records** — As Sales request a date change or cancellation for a test booking, review as Owner, then record the customer’s answer. Check that the prior approved quote remains intact. Open a legacy payment-tracked booking and confirm its existing transaction and invoice history still opens.
6. **Regression and mobile** — Open both PDFs, test notifications and status refresh, and check the Bookings, Operations and Booking changes pages on a phone. Complete a test trip and confirm the linked enquiry and quote show completion.
